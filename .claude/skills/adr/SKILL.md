# ADR 스킬 (금융나침반)

이 스킬은 네 가지 작업을 한다. 요청에 맞는 모드를 고르고, 설계 산출물을 다루는 작업이면 항상 "설계 검토 모드"를 함께 실행한다.

| 모드 | 언제 | 결과물 |
| --- | --- | --- |
| 작성 | 새 결정을 기록할 때, 설계 중 ADR이 정하지 않은 아키텍처 결정을 만났을 때 | 제안 상태 ADR |
| 검토 | ADR 초안·기존 ADR의 품질을 볼 때 | 체크리스트 결과와 수정안 |
| 설계 검토 | 설계서를 만들거나 고칠 때 (항상) | 정합성 점검표 |
| 대체 | 채택된 결정을 바꿀 때 | 새 ADR + 기존 ADR 상태 변경 |

## 1. 프로젝트 규칙 (가이드보다 우선)

ADR 문서(「금융나침반 아키텍처 결정 기록 (ADR)」)의 "작성 규칙"을 따른다. 참고 가이드와 다르면 이 규칙이 이긴다.

- ID는 `ADR-NNN`(3자리)이다. 번호는 다시 쓰지 않는다. 다음 번호는 기존 ADR(채택·제안·폐기 모두)의 최댓값 + 1이다.
- 본문 순서: 요약 문단 → 상태 줄 → 배경 → 선택지(표: 선택지·장점·단점) → 판단 기준 → 결정 → 결과(표: 구분·내용·대응). 근거가 길면 결정 뒤에 "근거"를 둔다.
- 상태는 `제안`(검토 중), `채택`, `대체됨`(대체한 ADR 번호를 적음), `폐기` 중 하나다.
- 결정을 바꿀 때는 기존 ADR 본문을 고치지 않는다. 새 ADR을 만들고, 기존 ADR 상태를 "대체됨 (ADR-NNN)"으로 바꾼다.
- 채택된 ADR은 아키텍처 설계서의 "결정 기록" 장에 결정 문장을 원문 그대로 인용한다.
- 배경·판단 기준·결과에는 근거 문서 위치를 적는다: 요구사항 ID(COR·SFR·SIR·DAR·PER·SER·QUR), 기획서 절(예: Ⅳ-4), 명세서 절(예: SRS 5.8).
- 결과 표의 "구분"은 장점, 감수할 점, 일정, 문서(상위 문서 개정 필요), 재검토 조건, 확인 필요, 미결 중에서 쓴다.
- 문체는 "~한다" 평서문, 한 문장 25자 안팎을 지향하고, 수치·날짜(YYYY-MM-DD)를 쓴다.
- 결정 하나에 ADR 하나다. 묶여 있으면 나눈다.
- 새 ADR은 항상 `제안`으로 시작한다. 채택은 팀(2인)이 결정한다. Claude가 임의로 `채택`으로 바꾸지 않는다.

## 2. 먼저 읽을 것 (모든 모드 공통)

1. 기존 ADR 전부: 정본은 Claude Docs 「금융나침반(가칭) 아키텍처 결정 기록 (ADR)」 https://claude.ai/artifact/EFhYEYAQWr6Ps7rgAxZtUg (docs 도구로 읽는다. 결정 요약 표의 상태 칸은 "ADR 상태" 드롭다운: 제안·채택·대체됨·폐기). `docs/금융나침반 아키텍처 결정 기록 (ADR).docx`는 내보낸 사본이라 최신이 아닐 수 있다.
2. 아키텍처 설계서 FC-SAD-001과 제안 ADR: Claude Docs 문서 https://claude.ai/artifact/DpPsH3e3zAj7CE1WqH2QrU ("아키텍처 설계서" 탭 12장, "설계서 ADR (004~017)" 탭 — ADR-012~017은 2026-11-19 채택, ADR-004~011은 제안). docs 도구로 읽는다.
3. 판단 근거 문서: `docs/금융나침반 요구사항 명세서.docx`(FC-SRS-001), `docs/금융나침반 아이디어 기획서.docx`(FC-PLN-001).

.docx는 python 표준 라이브러리(zipfile + xml)로 텍스트를 뽑아 읽는다. 읽은 뒤 "ADR 목록 표(ID·결정·상태·결정일)"와 "후속 결정(미결) 목록"을 머릿속에 정리하고 시작한다.

## 3. 작성 모드

1. ADR이 필요한 결정인지 판단한다 (`references/guide/adr을-위한-팀워크-질문.md`의 "정당화" 기준).
   - 필요: 구조, 비기능 요구(보안·가용성·성능), 모듈 결합, 외부 인터페이스, 라이브러리·프레임워크·도구, 되돌리기 어려운 데이터 결정.
   - 불필요: 한 모듈 안에서 끝나는 사소한 선택, 이미 다른 문서가 정한 것, 임시 실험. 이런 것은 설계서 본문에 쓴다.
2. 배경에는 문제와 제약을 쓴다: 팀 규모(2인), MVP·비상업 단계, 관련 요구사항 ID, 이 결정을 낳은 기존 ADR(예: "ADR-003 후속 결정").
3. 선택지는 2개 이상 쓴다. "~는 검토했나요?"라는 질문이 나올 대안(특히 기각된 기존 대안)을 빠뜨리지 않는다.
4. 판단 기준은 요구사항·제약에서 끌어온다. 기준마다 근거 ID를 붙인다.
5. 결정은 한두 문장의 명확한 입장으로 쓴다. 결정 문장만 읽어도 무엇을 하는지 알 수 있어야 한다.
6. 결과에는 감수할 점마다 대응을 짝지어 쓰고, 후속 결정·상위 문서 개정·재검토 조건을 넣는다.
7. 결정을 코드·CI 검사(적합도 함수)로 지킬 수 있으면 검사 방법을 결과의 대응에 적는다 (`references/guide/코드로-표현하는-의사결정의-적합도-함수.md`, ArchUnit 등).
8. 템플릿: `templates/project-adr.md`.
9. 작성 후 4장의 체크리스트로 스스로 검토한다.
10. 어디에 기록할지는 사용자에게 확인한다. 기본안은 ADR 문서 끝에 `제안` 상태로 추가하는 것이다. 사용자 문서를 고치기 전에는 반드시 허락을 받는다.

## 4. 검토 모드 체크리스트

`references/guide/좋은-adr-작성을-위한-제안.md`, `의사결정-지속가능성-기준.md`, `지속가능한-의사결정을-위한-지침.md`, 타이리·아커먼 템플릿을 프로젝트에 맞춰 줄인 목록이다. 항목마다 통과·보완·해당 없음으로 판정하고, 보완은 고칠 문장까지 제시한다.

- [ ] 구체성: 결정이 하나인가
- [ ] 타임스탬프: 작성일·결정일이 있는가
- [ ] 배경: 프로젝트 상황, 팀 구성, 우선순위, 왜 지금 정하는지가 있는가
- [ ] 선택지: 2개 이상이며 장단점이 대칭으로 적혔는가. 빠진 대안은 없는가
- [ ] 요구사항에 뿌리: 판단 기준이 요구사항 ID·제약에 연결되는가
- [ ] 근거: 왜 이 선택인지가 결정 자체만큼 분명한가
- [ ] 결과: 감수할 점마다 대응이 있는가. 후속 결정과 재검토 조건이 있는가
- [ ] 측정 가능: 결과를 수치나 자동 검사로 확인할 수 있는가
- [ ] 적정 설계: 2인 팀·MVP에 과하거나 모자라지 않은가
- [ ] 충돌: 채택 ADR과 충돌하지 않는가. 충돌하면 대체 절차를 밟았는가
- [ ] 상위 문서: 기획서·명세서 개정이 필요하면 결과 표 "문서" 행에 적었는가
- [ ] 형식: 1장의 순서·상태 값·ID 규칙을 지켰는가

## 5. 설계 검토 모드 (설계 산출물 ↔ ADR 정합성)

아키텍처 설계서와 후속 설계서(2A 데이터, 2B 화면, 3 인터페이스, 4 상세)를 만들거나 고칠 때 항상 실행한다.

1. 2장의 문서를 읽고 채택 ADR과 제안 ADR 목록을 만든다.
2. 산출물의 각 장(절)마다 확인한다.
   - 채택 ADR의 결정·감수할 점 대응과 어긋나는 내용이 있는가.
   - 채택 ADR이 정하지 않은 아키텍처 결정을 본문이 혼자 정했는가. 있으면 본문에서 빼고 작성 모드로 제안 ADR을 만든 뒤, 본문에는 "(ADR-NNN 제안)"으로 표시한다.
   - ADR이 요구한 후속 조치(후속 결정, 상위 문서 개정, 검증 테스트)가 반영됐는가.
   - 요구사항과 확정 도구(ADR-001 등)가 서로 부딪치는 곳이 있는가.
3. 각 장 끝에 `관련 ADR: ADR-NNN(무엇과 관련), ...` 한 줄을 둔다.
4. 결과를 `templates/consistency-review.md` 형식의 정합성 점검표로 남긴다 (아키텍처 설계서 12.3과 같은 형식). 충돌·미반영 항목은 조치(제안 ADR, 개정 요청, 후속 설계서로 이관)를 반드시 적는다.
5. 사용자에게는 점검표의 핵심(충돌·미반영 건수와 조치)을 짧게 보고한다.

## 6. 대체 모드

1. 바꾸려는 ADR의 결정과 결과를 다시 읽고, 무엇이 달라졌는지(새 정보, 재검토 조건 충족 등)를 배경에 쓴다.
2. 새 번호로 ADR을 작성한다. 배경 첫 줄에 "ADR-NNN을 대체한다"를 쓴다.
3. 새 ADR이 채택되면 기존 ADR의 상태만 "대체됨 (ADR-새번호)"으로 바꾼다. 기존 본문은 고치지 않는다.
4. 설계서의 "결정 기록" 장과 영향받는 절을 갱신하고, 적합도 함수(자동 검사)가 있으면 함께 고친다.
